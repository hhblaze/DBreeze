RandomKeySorter: полный lifecycle

1. ConvertKey/value сериализуются теми же DB converters.
2. Own keyПервый key clone становится identity map.
3. CoalesceОдна final insert/remove operation на key.
4. RentPending operations копируются в pooled buffer.
5. Sort/writeBinary lexicographic order, один table handle.
6. ResetFlush/commit/rollback/dispose освобождают state.

Что действительно удалено

  • Hex-string identity в локальном Net8.
  • Две конкурирующие коллекции insert/remove.
  • Отдельный RKS table cache поверх transaction cache.
  • Долгоживущий sort array: он заменён ArrayPool.

Что не было удалено

  • Auto-flush не был рабочим и в baseline: public поле историческое.
  • Сортировка по serialized key сохранена.
  • Explicit Flush и commit flush сохранены.
  • Табличный write cache существует на уровне Transaction.
Lifetime contract: key защищён clone, а value сознательно borrowed. Это экономит память, но мутация исходного массива до Flush/Commit влияет на результат. Для будущего изменения здесь нужен явный выбор владельца: clone и дополнительные allocations либо документированный borrowed buffer.

Retained state: теоретически текущий Net8 удерживает меньше метаданных на уникальный key: бинарный key вместо двухсимвольного hex, одна operation вместо двух maps, без дополнительного table cache. Измеренный RandomKeySorterBatch allocation одинаков: 363 B/op у обеих DLL.

Transaction: lifecycle, caches, collections, MultiSelect и vector

Owner и dispose

Все mutation/write-control paths вызывают EnsureTransactionOwner. Dispose при этом использует сохранённый owner id и может завершить locked session из другого thread; cleanup идемпотентен.

Commit/rollback reuse

RKS и transaction buffers очищаются после завершения. Repeated commit/rollback и открытые nested tables покрыты тестами; exception paths не переносят pending state.

Snapshots/caches

Write-table identity, committed read roots и visibility modifiers сохранены. Нет признака удаления hot read cache на уровне Transactions.

Collections

Replacement сначала материализует удаляемые DB keys. Equality определяется сериализованным/default контрактом DB, не произвольным comparer вызывающего Dictionary/HashSet.

MultiSelect

Net8 heap merge делает tie order детерминированным и проверяет размер каждого serialized key. API и результирующая последовательность тестами сохранены.

Vector

Handler создаётся лениво под синхронизацией; iterator освобождается при exception. Synchronous public insert path не превращён в скрытый deferred write.

Наблюдаемое ужесточение thread ownership — не просто implementation detail. Код, который раньше случайно мутировал одну Transaction из другого thread, теперь получает исключение вместо nondeterministic race. Это следует сохранять или менять только как публичное решение.

Coordinator / Locker / Unit

Главное архитектурное изменение — от process-wide broadcast gate и локальной pairwise проверки к очереди конфликтующих waiters с явными blocker edges.

Liveness evidence: прошли no-lost-wakeup, fairness, cleanup-on-notify-failure и three-way deadlock tests. Новая схема исправляет класс зависаний, который pairwise алгоритм не мог доказательно исключить.
Цена: waiter object, gate и blocker collections добавляют краткоживущие allocations. BDN allocation gate сработал, хотя concurrent retry меняет знак. Нужен специальный deterministic allocation harness без scheduler noise перед оптимизацией; нельзя возвращать global broadcast только ради этих 150 B.

Journal: protocol, recovery и compaction

Storage identity

_DBreezeTranJrnl, таблица DBreeze.TranJournal.

Marker key

Transaction number, 8-byte big-endian encoding.

Payload

Исторические UTF-8 XML fragments: <string>table</string> в исходном table order.

Recovery

Schema route открывает таблицу, включая AlternativeTablesLocations.

Allocate tx idMonotonic journal transaction number.
Collect tablesИмена ITransactable в commit order.
Persist markerDurable journal запись до finish.
Finalize tablesКаждая таблица завершает commit.
Delete markerТолько после полного success.
Recover/reuseStartup recovery, затем RemoveAll(true).

Startup cleanup и runtime compaction нельзя смешивать. После startup recovery текущий код переиспользует LTrie через RemoveAll(true). При runtime росте journal примерно выше 10 MB по-прежнему выполняются Storage.RecreateFiles(), dispose и reopen. Disk bytes и marker ordering не изменены.

Открытые риски и приоритеты

P0 — не ломать

  • 148-record API manifest и non-sealed RandomKeySorter.
  • Journal marker bytes/order и marker-before-finalization protocol.
  • Transitive deadlock detection, conflict-aware FIFO и all-path waiter cleanup.
  • Strict disk reopen обеими версиями.

P1 — измерить/зафиксировать

  • Coordinator allocation gate: сделать deterministic counter per wait/reservation и подтвердить механизм.
  • Явно документировать borrowed RKS value и thread-owner mutation rule.
  • Оставить auto-flush field для API, но не выдавать его за рабочую memory bound.
  • Повторить noisy disk timing на изолированном volume/длинном job.

P2 — расширить доказательства

  • Runtime suite для net6/net472, если эти consumers production-critical.
  • Отдельная двоичная crash-инъекция baseline и current, хотя historical payload oracle уже проходит.
  • Peak retained bytes для RKS с длинными keys/values, не только B/op.

P3 — hygiene

  • Объяснить историческое имя DBreeze.Net5 при target net6.0.
  • Синхронизировать comments про auto-flush/borrowed ownership.
  • Автоматически генерировать эту decision matrix из manifests там, где возможно.
Owner decision required: оптимизация allocations coordinator не должна ослаблять fairness/deadlock guarantees; clone value в RKS не должен вводиться «для безопасности» без оценки memory contract; cross-thread mutations не должны снова становиться silent races.

Guardrails для последующих LLM-изменений

  1. Сначала раскрывать effective source graph. Не переносить вывод из common в Net8 или наоборот без проверки csproj bindings.
  2. API manifest — P0 gate. Сравнивать visibility, inheritance/type flags и constraints, а не только имена public methods.
  3. Никогда не менять converter/key encoding/XML journal payload. In-memory ByteKey допустим; on-disk bytes — нет.
  4. Сохранять final-operation-wins и reset boundaries RKS. Auto-flush field исторически no-op; не изобретать скрытые flush points.
  5. Фиксировать ownership. Key owned, value borrowed до flush/commit, Transaction mutations owned creator thread; любое изменение — документированный contract decision.
  6. Не держать coordinator/state locks во время dispose или disk I/O. Wakeups адресные, cleanup выполняется во всех exception paths.
  7. Deadlock detection должна быть transitive. Pairwise check недостаточен; тестировать цикл минимум из трёх writers.
  8. Collection identity задаёт DB serialization. Caller comparer не может менять, какие физические keys считаются равными.
  9. Проверять каждую row MultiSelect. Нельзя возвращать validation только на первый cursor element.
  10. Disk gate всегда двунаправленный. Create/read/extend/re-read двумя DLL плюс logical и strict physical manifest.
  11. Perf утверждения делать только по стабильным сценариям. Показать raw runs, spread, retry и allocations; не выбирать удобный прогон.
  12. Любая memory optimization должна считать retained lifetime. Отличать pooled transient buffer, borrowed caller buffer и transaction-long dictionary state.
