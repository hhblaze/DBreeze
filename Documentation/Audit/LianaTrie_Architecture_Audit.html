Ни один активный архитектурный механизм LianaTrie не исчез без замены. Snapshot cache generation nodes, dirty-map save, reservation policy, overwrite/append, read-root visibility, nested ownership и storage commit boundary сохранены. Изменены identity, внутренние traversal algorithms и allocation profile.

Сохранять

Pointer-keyed committed-node cache, explicit DFS для full/range/skip, exact-size .NET 8 serialization, structural nested-key cache, monotonic table version.

Не переоценивать

SaveGenerationMap не равен durable flush. Explicit stack пока покрывает не все traversal families. Pointer cache корректен только внутри строго очищаемого epoch.

Унаследованный lifecycle-риск

Early dispose изменённой nested table остаётся отдельным baseline-дефектом. Потеря dirty generation-map при mixed write epoch минимизирована и исправлена без изменения API, journal или wire format.

4. Lifecycle, visibility и разные значения слова flush

MutationNode получает ToWrite, table становится modified.
Generation mapDirty nodes живут в writer-root.
SaveGenerationMapСтруктурные bytes уходят в transaction storage.
RKS FlushPending sorted операции materialize в trie.
Transaction commitКоординация таблиц, journal и read-root version.
Storage commitPhysical buffers, rollback data и durable file state.
Внутри LianaTrie не было и сейчас нет политики «flush после N insert». AutomaticFlushLimitQuantityPerTable принадлежит уровню Transactions/RandomKeySorter; durable flush и fsync принадлежат Storage. SaveGenerationMap делает структуру читаемой в текущем transaction view, но сам по себе не обещает durability.

Commit

Nested coordinator и root завершают transactional phase; после completion node snapshot cache очищается, generation map считается сохранённой, table version меняется.

Rollback

Storage view и root откатываются; cache epoch заменяется, чтобы physical pointer не адресовал образ из предыдущего состояния.

Recreate / Dispose

Reset() оставляет coordinator reusable для RemoveAll(true). Dispose() terminal/idempotent и освобождает lock.

7. Что выглядит удалённым, но сохранено иначе

Cache

Сохранён cache старых committed kids. Удалён Base64(path), а не snapshot. Неактивные value dictionaries не были рабочим cache baseline.

Write buffering

Dirty generation map, node reservation и Storage buffers сохранены. LianaTrie-level flush counter не существовал.

Pointer policy

Overwrite-in-place и append с parent propagation сохранены; pointer теперь дополнительно служит cache identity.

Read snapshots

Transaction read-root по-прежнему refresh-ится после commit/rollback. Версия стала monotonic token вместо wall-clock ticks.

Nested ownership

Несколько root views и quantityOpenReads сохранены; Reset отделён от terminal resource disposal.

Disk bytes

Modern primitives меняют construction pipeline, но raw deterministic output совпадает с baseline.

8. Cache, cache epoch и read visibility

Почему pointer-key безопаснее и дешевле

Baseline строил массив logical path и Base64 string даже ради lookup одного physical node. Current использует уже имеющийся dynamic pointer как ulong: меньше transient allocations, короче hashing и нет зависимости identity от построения path.

Цена решения

Pointer unique не навсегда, а только внутри physical state таблицы. Commit completion, rollback и recreation обязаны заменить dictionary до следующего committed read. Любой новый lifecycle path должен соблюдать этот invariant.

First-image-only, а не общий data cache

При первом overwrite существующего node cache запоминает KidsBeforeModification. Повторные writes в том же epoch не заменяют образ. Он нужен read-root для topology visibility и не кеширует произвольные values.

Почему остаточный cachedGenerationMapLine всё ещё виден

Некоторые старые recursive helpers продолжают строить path как traversal state, а GenerationNodeRead сохраняет совместимый параметр. Pointer cache его уже не использует. Это modernization tail и источник лишних allocations, но не потеря cache semantics.

10. Nested tables: identity, ownership и lifecycle

Structural key cache

Base64-string identity заменена comparer-ом байтов. Stored key clone — осознанная retained allocation: без него мутация caller buffer разрушила бы hash dictionary. Net8 использует SequenceEqual и HashCode.AddBytes; shared — deterministic loop/FNV-style hash.

Root views

Coordinator по-прежнему различает write root и read roots, считает открытые readers и не обязан закрывать их безусловно на каждом commit. Rename/remove обновляют key→pointer association по содержимому ключа.

Inherited lifecycle caveat: закрытие изменённой nested table до master Commit может потерять её dirty state. Это одинаково в baseline/current и потому не исправлялось совместно с refactoring regressions.

12. Память: transient allocations и retained state

Снижено

  • Base64/path allocations node cache.
  • Base64 lookup nested cache.
  • Temporary endian arrays и concatenations.
  • 256-slot serialization buffer там, где reservation меньше.
  • Новые backing arrays в RemoveAllKids.

Retention исправлен

  • Generation map очищает отрезанные references.
  • Cached path invalidates при shrink.
  • Terminal Dispose освобождает locks.
  • Cache dictionary заменяется на lifecycle boundary.

Осознанно удерживается

  • Один clone каждого открытого nested key.
  • Один committed kids image на изменённый physical node в epoch.
  • O(depth) frames полного/range/skip traversal.
  • Path copies в оставшихся recursive families.
Benchmark allocation gate: рост не обнаружен ни в одном из 72 сценариев. На ключевых workloads: random insert −76.20%, update −95.39%, partial read −79.92%, nested scan −87.63%.

15. Открытые риски и следующий этап

P0
Не нарушать cache epoch. Любой новый path, способный переиспользовать physical offsets, должен очистить pointer-keyed _nodes до committed read.

Сохранить recreate gate. RemoveAll(true) → insert/nested → commit → reopen, повторная recreation и idempotent terminal dispose обязательны.

16. Заключение

Рефакторинг не демонтировал скрытую cache/flush архитектуру LianaTrie. Он заменил дорогую logical-path identity на pointer identity, рекурсивные hot-path обходы — на explicit frames, а временные serialization buffers — на exact modern primitives. Старые boundaries между trie, transaction и storage сохранены.

Наблюдаемые пользовательские изменения ограничены исправлением ошибочных side effects и формализацией partial-read edge cases. Формат файлов доказан не только чтением в обе стороны, но и raw byte identity. Memory и performance envelope улучшены по измеренным сценариям.

Рекомендация: текущую LianaTrie-архитектуру можно принимать как backward-compatible refactoring. Потеря dirty generation-map при ChangeKey исправлена и закрыта regression/disk/performance gates; оставшуюся recursion и early nested dispose вести отдельными change sets.
