Главный вывод

Активный функциональный механизм LianaTrie не был доказанно потерян. Самое заметное «исчезновение cache» является заменой identity: committed snapshot cache generation nodes сохранён, но вместо полного logical path в Base64 индексируется физическим pointer.

Главное недопонимание, которого следует избегать: `SaveGenerationMap()` — не durable flush. Он материализует dirty generation nodes для синхронного чтения через write-root. Буферизация/flush RandomKeySorter принадлежит Transactions, а запись буферов и fsync — Storage.
Главный найденный lifecycle-риск уже исправлен в working tree: `RemoveAll(true)` больше не использует terminal `Dispose()` координатора nested tables; reusable `Reset()` очищает состояние, не уничтожая lock и не делая текущую `LTrie` неработоспособной.

Карта lifecycle и visibility

1. Mutationwrite-root меняет generation map; `TableIsModified=true`, `GenerationMapSaved=false`.
2. Structural save`Save_GM_nodes_Starting_From` пишет nodes снизу вверх и обновляет parent pointers.
3. Old image cacheПеред overwrite первая committed-версия kids сохраняется по physical pointer.
4. Commit / rollbackStorage завершает транзакционный цикл; cache epoch очищается.
5. Read-root refresh`DtTableFixed` меняется; Transaction заменяет устаревший cached read-root.

Читатель с useCache=true использует committed root и при overwrite получает старый образ generation node из `LTrieWriteCache._nodes`. Пишущая транзакция читает через write-root; перед такими read API вызывается `SaveGenerationMap()`, чтобы in-memory parent/child pointers стали согласованными. Это copy-on-overwrite snapshot на уровне узлов, а не общий value cache и не полноценный MVCC с произвольным количеством версий.

Что действительно удалено

Функциональная подсистема не удалена. Удалены или вытеснены четыре implementation strategy:

  1. Logical path как identity cache entry. Полный byte path + Base64 заменён physical pointer.
  2. Recursive helpers для full/from-to/skip. Их обязанности перенесены в explicit DFS frames.
  3. Лишние zero-fill и intermediate arrays. Новые массивы CLR уже zeroed; Net8 полностью заполняет uninitialized buffers.
  4. Wall-clock ticks как invalidation token. Назначение сохранено через monotonic version.

Fresh allocation `_f` в `RemoveAllKids()` также удалён, но это не cache policy: массив теперь очищается и переиспользуется с полным reset логического состояния.

Что выглядит удалённым, но сохранено иначе

Cache

Сохранён cache старых committed kids generation node. Изменены key identity и allocation profile. Это не data cache значений: `_values` и `dDynamicDataBlocks` уже не работали в baseline.

Write buffering

Сохранены dirty generation map, reservation и storage buffers. Нет нового или исчезнувшего «flush после N insert» внутри LianaTrie.

Pointer policy

Сохранено решение overwrite-in-place при достаточной reservation и append с propagation parent pointer при росте.

Read snapshots

Transaction по-прежнему кеширует read-root и обновляет его после commit/rollback. `DtTableFixed` стал надёжнее, но перестал быть временем.

Nested ownership

Coordinator продолжает держать несколько root views и `quantityOpenReads`; commit/rollback не означает безусловное закрытие всех читателей.

Disk format

Big-endian fields, reservation padding, pointer length и node/value protocols сохранены. Net8 меняет только способ сборки buffer.

Исправленные старые side effects

  • Insert-if-absent existing key: больше не dirty, не удаляет nested table, не вызывает лишний commit/version cycle.
  • Remove missing key: больше не считается mutation.
  • RemoveAll with recreation: reset coordinator отделён от terminal resource disposal.
  • RemoveAllKids: очищает value pointer, count, empty-value flag и extrema.
  • Partial value: eager и lazy paths получили согласованные границы и overflow guards.
  • GenerationMap shrink: больше не удерживает обрезанные node references.
Эти изменения намеренно не воспроизводят каждый ошибочный side effect эталона. Они сохраняют заявленный контракт операций: no-op не должен повреждать nested data или превращать таблицу в modified.

Спорные места и открытые риски

1. Traversal-переход завершён не полностью

Deep full scan защищён explicit stack, но start-from, skip-from, min/max, starts-with и closest-prefix ещё рекурсивны. Нужны deep-key tests отдельно для каждого семейства и последующая iterative миграция с oracle.

2. `cachedGenerationMapLine` стал мёртвой частью внутреннего интерфейса

`GenerationNodeRead` принимает path, но lookup выполняется только по pointer. В remaining recursive code path всё ещё копируется на каждом уровне. Это не correctness regression, но поддерживает ложную архитектурную модель и лишние allocations.

3. Physical-pointer cache требует жёсткой epoch discipline

Корректность зависит от очистки `_nodes` на каждом событии, которое может переиспользовать physical offsets. Текущие commit/rollback/recreate paths это делают; новые lifecycle paths обязаны сохранять invariant.

4. Platform parity partial reads

Net8 `ReadKeyValue` проверяет `valueLength > Int32.MaxValue`; common full `ReadKeyValue` всё ещё делает прямой cast в одном path. Для нормальных DB файлов это недостижимо, но corrupt/hostile storage semantics различаются.

5. Имя `DtTableFixed` теперь вводит в заблуждение

Значение больше нельзя трактовать как `DateTime.Ticks`. Публичную сигнатуру менять не нужно, но внутренний контракт следует документировать как opaque monotonic version.

6. Structural key hash различается по платформам

Common comparer использует deterministic FNV-like hash, Net8 — process-randomized `HashCode`. Dictionary живёт только в памяти, поэтому disk/order compatibility не затрагивается; возможна только разница performance profile.

Границы ответственности LianaTrie / Transactions / Storage

LianaTrie

  • Trie topology, kids/value pointers и reservation.
  • Dirty generation map и writer-visible structural save.
  • Committed old-image cache при node overwrite.
  • Nested trie lifecycle внутри master table.

Transactions

  • Выбор write-root против committed read-root.
  • Кеширование read-root и refresh по `DtTableFixed`.
  • `RandomKeySorter.Flush()` перед transaction commit.
  • Locking, table reservation и multi-table atomicity.

Storage

  • Sequential/random write buffers.
  • Rollback и rollback-helper files.
  • Физический flush/fsync и backup stream.
  • Read view committed/uncommitted bytes.

Практическая формулировка

SaveGenerationMap делает trie structurally readable. Commit завершает transaction semantics. Storage flush делает bytes durable. Эти три события нельзя называть одним словом «flush» без уточнения слоя.

Common и Net8: фактическая композиция

Net8-проект не содержит независимую копию всей LianaTrie. Он связывает общие файлы, поэтому common correctness-изменения автоматически входят в Net8:

Linked из common

LianaTrie.cs, LTrieRootNode.cs, `Iterations/Forward.cs`, `Iterations/Backward.cs`, `NestedTable.cs`, `NestedTableInternal.cs`.

Net8 specialized

LTrieGenerationMap, LTrieGenerationNode, LTrieKidsInNode, LTrieRow, LTrieWriteCache, coordinator/storage nested tables и small data holders.

Следствие: iterative traversal является общей оптимизацией всех проектов, которые подключают эти файлы; `BinaryPrimitives`, spans и `AllocateUninitializedArray` остаются Net8-only. Correctness fixes в duplicated specialized файлах необходимо зеркалить по платформенной матрице.

  • Deep stack safety remaining start/prefix/min/max families — не доказана.
  • Pointer-cache invariant при будущих новых recreation paths — требует обязательного lifecycle review.
  • Common-platform behavior на corrupt value length > Int32.MaxValue отличается от Net8.

Рекомендации и следующий приоритет

P0
Закрепить deep traversal matrix для оставшихся recursive API. Отдельно start-from, skip-from, min/max, starts-with и closest-prefix в обе стороны; глубина должна превышать безопасный recursive stack.
P0
Сохранить lifecycle regression как обязательный gate. `RemoveAll(true) → insert/nested → commit → reopen`, несколько recreation и idempotent dispose для memory/disk.
P1
Завершить pointer-cache migration. Удалить внутренний `cachedGenerationMapLine`, заменить depth/path-copy в remaining traversal на frame state, затем повторить oracle и benchmarks.
P1
Формализовать cache-epoch invariant. Любой новый path, способный переиспользовать offsets, обязан очистить `_nodes` до последующего committed read.
P1
Выровнять oversized/corrupt read guards. Общие и Net8 implementations должны выдавать одинаковую контролируемую ошибку без unchecked cast.
P2
Документировать `DtTableFixed` как version token. Не менять public API, но убрать трактовку как DateTime из комментариев и внутренних имён при следующем совместимом refactor.
P2
Удалить commented cache archaeology отдельным cleanup-коммитом. Это уменьшит вероятность, что следующая LLM сочтёт `_values` или dynamic-block dictionaries потерянной рабочей системой.
P2
Добавить sparse fan-out benchmark. Он напрямую измерит эффект `MinKid..MaxKid` и стоимость поддержания extrema.
