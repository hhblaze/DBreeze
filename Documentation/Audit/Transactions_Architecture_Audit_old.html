Главный вывод

Кэши, batching, reservation и crash-recovery не были бездумно удалены. Основная архитектура сохранена, но границы ответственности стали строже: Net8 получил собственные hot paths, ожидание записи стало per-waiter и графовым, а journal разделил in-memory bookkeeping, durable marker I/O и table-finalization.

Ключевое недопонимание №1: `AutomaticFlushLimitQuantityPerTable` уже в эталоне не управлял flush — вызовы были закомментированы, а XML-комментарий говорил `NOT USED ANYMORE`. Восстанавливать flush после N операций нельзя: он ломает быстрый смысл `TryGetValueByKey` и object identity batching.
Ключевое недопонимание №2: удаление `RandomKeySorter.tbls` в Net8 не удалило cache write-таблиц. Реальный transaction-level cache `transactionWriteTables` сохранён; RKS cache лишь дублировал его.
Подтверждённая публичная регрессия: эффективный эталонный `DBreeze.Transactions.RandomKeySorter` был наследуемым, текущий Net8 тип стал `sealed`. Reflection diff с проверкой type flags нашёл 1 отличие среди 6 публично видимых Transactions-типов.

Lifecycle транзакции после рефакторинга

1. CreateCoordinator удаляет stale transaction того же thread id до создания locked session.
2. ReservePer-waiter gate, fair queue и wait-for graph резервируют write patterns.
3. MutateTransaction caches LTrie; RKS coalesces final operations; owner thread проверяется.
4. FlushRKS сортирует keys; removes выполняются перед inserts. Commit вызывает Flush автоматически.
5. PrepareSingle-table идёт коротким путём; multi-table получает transaction number и rollback files.
6. JournalDurable XML marker → ITRCommitFinished tables → durable marker removal.
7. CleanupUnregister/rollback и gate wakeups выполняются без slow I/O под coordinator global locks.

Ключевая durability-последовательность multi-table commit не изменилась: recovery marker становится durable до финализации таблиц и удаляется только после успешной финализации всех таблиц. Изменилось то, какие lock-и удерживаются вокруг этапов.

RandomKeySorter: что изменилось архитектурно

Эталонная модель

  • Hex string как dictionary identity serialized key.
  • Раздельные insert/remove dictionaries.
  • _cnt, isUsed, WasAutomaticallyFlushed.
  • Собственный cache LTrie tables.
  • LINQ sorting при Flush.

Net8 модель

  • Одна финальная операция на binary key.
  • Key clone + cached FNV-1a hash.
  • Value borrowed до flush/commit.
  • Pooled sortable operation array.
  • Transaction cache выдаёт LTrie.

Legacy targets

  • Сохраняют hex-based data structure.
  • Получили owner checks и last-operation-wins.
  • Исправлен ConvertValue.
  • Добавлен Reset для rollback.
  • Не используют недоступные modern APIs.

Auto-flush: исторический комментарий против реального кода

Старое summary всё ещё упоминало flush после превышения default 10 000, но фактическое поле уже было 1 000 000, а оба threshold checks были закомментированы. Следовательно, рефакторинг не удалил работающий механизм; он сделал no-op контракт явным. Причина отключения остаётся архитектурно важной: после скрытого flush отсутствие key в RKS уже не означает отсутствие текущего value — пришлось бы читать LTrie/storage, и object-layer identity path потерял бы O(1) pending lookup.

Last-operation-wins

Новая модель определяет результат только последней операцией на serialized key. Это устраняет зависимость от WasAutomaticallyFlushed. При самом Flush исторический порядок «все remove, затем все insert» сохраняется для разных pending keys; для одного key остаётся только финальная операция.

Borrowed value — осознанный контракт: caller-owned mutable byte[] нельзя менять до explicit Flush или Commit. После flush RKS больше не держит pending reference. Key, напротив, должен быть owned и clone-ится при помещении в dictionary.

Transaction: caches, visibility и modern merge

Сохранённые caches

  • transactionWriteTables: table name → writable LTrie; основной bulk-write cache.
  • transactionReadTables: LTrie + DtTableFixed + read root; transaction visibility cache.
  • _openTable: счётчик открытий для симметричного schema cleanup.
  • Parallel read path по-прежнему может обходить owner check через явно вычисленный ignoreThreadIdCheck.

Новые lifecycle-инварианты

  • State-changing operation принадлежит creating thread.
  • Commit сначала flush-ит RKS, затем vector/text handlers, затем coordinator commit.
  • Rollback очищает pending RKS даже при ошибке coordinator rollback.
  • Dispose idempotent и освобождает locked session по сохранённому thread id.

Multi-select

Эталон выполнял N-way merge через dictionaries enumerator/current row и повторный линейный выбор минимального или максимального key. Net8 хранит по одному cursor на таблицу в PriorityQueue. Priority включает binary key и стабильный ordinal table sequence, поэтому одинаковые keys сохраняют детерминированный tie order. После каждого MoveNext проверяется serialized key length; все enumerators закрываются в finally.

Не расширять контракт: все участвующие rows обязаны иметь keys одинаковой сериализованной длины. Это исторический контракт Multi_Select*, а не ограничение, которое следует «исправить» variable-length comparer-ом.

Coordinator, TransactionTablesLocker и TransactionUnit

От broadcast gate к wait-for graph

Старый единственный ThreadsGator не моделировал ownership конкретного ожидания: освобождение одной transaction будило всех. Текущий WriteReservationWaiter содержит transaction id, копию requested tables, собственный gate и текущий список blockers. Очередь допускает параллелизм несвязанных requests, но запрещает later conflicting request обходить earlier waiter.

Deadlock

Эталон находил прямую взаимную зависимость по write/awaiting tables. Текущий iterative DFS идёт по blocker graph и обнаруживает цикл любой длины. Deadlock по-прежнему завершает исходную transaction исключением TRANSACTION_IN_DEADLOCK.

Failure cleanup

Coordinator lock защищает только waiter graph. Gate disposal, unregister, rollback и table I/O выполняются после выхода из него. Неожиданная ошибка сохраняет внешний contract TRANSACTION_TABLE_WRITE_REGISTRATION_FAILED.

Table locker

Accepted/waiting dictionaries и FIFO sequence сохранены. Исправлено только правило допуска: earlier conflicting exclusive waiter теперь нельзя обойти бесконечным потоком shared sessions.

TransactionUnit

Коллекции write reservations создаются lazy. Методы возвращают snapshots, а не mutable внутренний list, что делает построение wait graph стабильным после освобождения unit lock.

Запрещённая будущая оптимизация: не переносить dispose/rollback/I/O обратно под _sync_transactions или _sync_dl. Эти locks должны защищать только coordinator state, иначе unrelated transactions снова станут сериализоваться на диске.

TransactionsJournal: protocol сохранён, lock boundary изменена

1. SnapshotКопия transaction tables под state read lock.
2. Marker addXML payload добавляется и commit-ится под journal I/O lock.
3. FinalizeITRCommitFinished каждой таблицы без state/journal lock.
4. Marker removeУдаление marker и durable commit под journal I/O lock.
5. CompactПри empty state и >10 MB повторная проверка, RecreateFiles и reopen.

Что осталось byte-compatible

  • Имя storage: _DBreezeTranJrnl.
  • Journal table name: DBreeze.TranJournal.
  • Key: transaction number в 8-byte big-endian representation.
  • Value: UTF-8 результат исторического XML serializer списка table names.
  • Порядок table names: insertion/enumeration order исходного per-transaction dictionary.
  • Recovery marker durable до table finalization и удаляется только после успеха.

Два разных сценария очистки

Startup / recovery

RecreateJournalStorage() вызывает LTrie.RemoveAll(true) и продолжает использовать тот же экземпляр. Это опирается на исправленный reusable lifecycle LianaTrie.

Runtime compaction >10 MB

Сохранился полный путь Storage.RecreateFiles() → dispose LTrie → новый StorageLayer/LTrie. Удалять reopen из этого path без отдельного аудита нельзя.

Recovery ownership улучшен: journal больше не угадывает storage settings по physical path. DBreezeSchema.OpenTableForRollbackRecovery знает реальный storage route, включая alternative disk storage.

Что выглядит удалённым, но функционально сохранено

RKS table cache

Локальный tbls удалён только в Net8. Writable LTrie всё ещё кешируется в Transaction.transactionWriteTables.

Auto-flush

Не потерян: он уже не работал в эталоне. Сохранено публичное поле как compatibility-only no-op.

Sorted flush

Hex ordering заменён binary span ordering; оба дают lexicographic byte order. Removes по-прежнему идут перед inserts.

Read snapshots

Rtbe, read root и version refresh не удалены. Parallel reads остаются отдельным opt-out path.

Write reservation

Глобальный gate исчез, но сам механизм усилен: per-waiter gates, fair sequence и graph blockers.

Journal compaction

Порог 10 MB и runtime reopen сохранены. Без reopen работает только startup/recovery RemoveAll path.

Journal serialization

State write lock больше не охватывает всю операцию, но durable journal I/O строго сериализован отдельным monitor.

Legacy targets

Common/NetStandard не обязаны повторять Net8 data structures, но coordinator и lifecycle invariants синхронизированы без modern-only API.

Vector k-means

Физический common source не равен compiled feature: эталонный Net8 его тоже не включал.

Observable exception differences

Некоторые invalid-argument paths Net8 теперь выбрасывают более точный ArgumentNullException вместо generic Exception; coordinator cleanup сохраняет исторические DBreeze exception codes, но inner exception и stack стали информативнее. Guardrails для будущего LLM-рефакторинга

  1. Всегда строить effective source graph из csproj. Не сравнивать только физические папки common/Net8.
  2. Не восстанавливать auto-flush по AutomaticFlushLimitQuantityPerTable. Это compatibility field, не policy.
  3. Не возвращать RKS-local LTrie cache в Net8. Сначала учитывать transactionWriteTables.
  4. Не clone-ить RKS value автоматически. Borrowed lifetime — согласованный performance contract; key должен оставаться owned.
  5. Не менять last-operation-wins. Результат не должен зависеть от того, был ли ранее explicit/automatic flush.
  6. Не выполнять rollback, dispose или table I/O под coordinator global locks.
  7. Не упрощать wait-for graph до pairwise deadlock check. Three-way cycle является regression test.
  8. Не позволять later conflicting waiter обойти earlier waiter. Unrelated reservations при этом не надо глобально сериализовать.
  9. Не менять journal XML, key encoding, file name или marker order.
  10. Различать startup RemoveAll и runtime 10 MB compaction. Только первый path переиспользует тот же LTrie без reopen.
  11. Не копировать Vector_kmeans в Net8 как «утерянный файл». Он не был compiled в эталоне.
  12. Public API diff обязан включать type attributes. Методы/свойства не обнаруживают sealed.
