Итог аудита

В текущем Net8-контуре обнаружен широкий, но неоднородный набор проверок. Regression runner содержит 80 зарегистрированных сценариев, BenchmarkDotNet — 59 измеряемых методов в 9 классах. Benchmark-проект дополнительно выступает как compatibility и audit harness.

Главное покрытие

Transaction lifecycle, CRUD, ranges, nested tables, RKS, collections, objects, journal recovery, resources, TextSearch, remote storage и concurrency.

Статус данных

Фактические PASS/FAIL, latency и allocation results не заявляются: этот документ построен без запуска workload’ов.

Порядок ревизии

Сначала correctness и короткие edge cases, затем contention и disk compatibility, после этого — длительные million-row workloads.

Методика и границы

Режим аудита: статический просмотр исходников и project files. Время оценивается по fixture size, числу операций, I/O и синхронизации.

Включено

  • Все записи из массива Program.tests.
  • Все 59 методов с [Benchmark].
  • Fixture/setup, parameters, worker count и operations per invocation.
  • Ручные probes, audit workers и historical suite modes.

Не является отдельной строкой

  • Приватные assertion/helper-методы.
  • Модели, persistence и renderer без workload.
  • Старые target frameworks вне Net8-проектов.
  • Фактические runtime results.
Как читать время
Для regression указана оценка одного entry point вместе с fixture и cleanup. Для BDN — workload iteration; setup и полный class run показаны отдельно. Disk ranges шире из-за filesystem cache, flush, reopen и типа носителя.
